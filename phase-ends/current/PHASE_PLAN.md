- Observation before fixing: T1 captures one instrumented run and classifies where the chain stops (no VI retrace / no GX batch / batch but no present / presented but black). That class picks which hypothesis T2 tests first, so each later run is one cheap isolating run.
- Hypotheses cheapest first (generation plan): (a) regenerated symbols drop HLE/idle hooks silently; (b) the uncommitted edits (sampler hunk off via a scratch copy, per the developer's choice); (c) XFB/VI present or GL context; (d) blank memory card stalling a prompt. T2 tests them in the order T1's class implies and stops at the first that flips the result.
- The fix is its own task (T3) so the expert lands it with the backup, the branch and the doc, and the developer confirms the title screen there (`review: yes`).
- T1 is small (≤ 10 calls: backup, build, one bounded run, grep) so its expert does it with no coder (developer: minimize subagents). T2 and T3 are edit-build-run loops → one in-house coder each.
- Branch: per the developer's decision, `harvest-moon-fixes` is created at 5ae33b9 without touching the working tree (`git -C gcn-recomp branch harvest-moon-fixes 5ae33b9; git -C gcn-recomp switch harvest-moon-fixes` keeps local edits since HEAD is the same commit).
